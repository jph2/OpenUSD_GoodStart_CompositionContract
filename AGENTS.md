## Keep the contract skill synchronized

The maintained reusable skill is [skills/openusd-composition-contract/SKILL.md](skills/openusd-composition-contract/SKILL.md). `CompositionContract.md` remains the rule owner; the skill translates it into agent workflow guidance. Its bundled reference and `references/source.json` are generated by `tools/sync_composition_skill.py`.

- **Every repository change includes skill maintenance.** Review whether changed rules, examples, folder/layout conventions, tooling capabilities, evidence limits or workflows affect the skill. Update its instructions and UI metadata in the same task where relevant. Changes to `CompositionContract.md` always require refreshing the bundled reference and provenance. A source hash update alone does not update the skill's interpretation of changed rules.
- **Version in lockstep:** `SKILL.md` metadata.version and the generated manifest's version/contract_version must exactly match the main paper's Status version. Change the contract version first when its requirements change, then update the skill and active README version labels against that revision. Editorial or skill-only clarifications may retain the contract version; content hashes identify the actual snapshot. Keep historical example profiles and evidence at their own recorded versions until re-evaluated.
- After reviewing/updating the maintained skill, run `python tools/sync_composition_skill.py --install` to refresh the reference, version, manifest and personal installation. The default installation is `$CODEX_HOME/skills/openusd-composition-contract`, or `~/.codex/skills/openusd-composition-contract` when unset, matching this host's skill catalog. `--skills-root <directory>` selects another configured personal skills directory. Refreshing this managed installation is part of the requested synchronization workflow; do not overwrite unrelated skills or unresolved edits in an installed copy.
- Run `python tools/sync_composition_skill.py --check --install` for a read-only comparison of source-derived artifacts and the installation, using the same skills directory. This checks synchronization only; it is not a USD test or semantic acceptance result. If installation is unavailable on another host, synchronize the repository package, record the installation gap and do not claim the personal copy is current.
- Record the version, relevant skill changes (or why no guidance change was needed), actual synchronization outcome and remaining limitations in `harness/STATE.md`. Never hand-edit the generated reference or manifest, and never update only the installed copy.
